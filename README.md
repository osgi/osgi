# OSGi Specification Project

This repository is the entry point of the
[OSGi Specification Project](https://projects.eclipse.org/projects/technology.osgi).
Use it for **requirements, ideas and issues for new and future OSGi
specifications**: open an [issue](https://github.com/osgi/osgi/issues) or
start a [discussion](https://github.com/osgi/osgi/discussions). The work is
planned on the [OSGi Overview](https://github.com/orgs/osgi/projects/1)
project board.

The specifications themselves are developed in one repository per
specification, listed [below](#repositories). Each holds the API
(`api/`), the specification chapter (`spec/`) and the TCK (`tck/`) of its
specification. Report a bug in, or propose a change to, an existing
specification in its repository.

## Where things are

| What | Where |
|------|-------|

| Core and Compendium books, aggregate jars `osgi.core`, `osgi.annotation`, `osgi.promise` | [osgi.core](https://github.com/osgi/osgi.core), [osgi.cmpn](https://github.com/osgi/osgi.cmpn), [osgi.annotation](https://github.com/osgi/osgi.annotation), [osgi.promise](https://github.com/osgi/osgi.promise) |
| Parent pom of all specification repositories | [org.osgi.maven.pom](https://github.com/osgi/org.osgi.maven.pom) |
| Shared TCK support | [org.osgi.test.support](https://github.com/osgi/org.osgi.test.support) |
| Released reference implementations and TCKs of earlier releases | [osgi/materials](https://github.com/osgi/materials) |
| CI and release workflows of all repositories | [osgi/.github](https://github.com/osgi/.github) |
| Configuration of the GitHub organization | [osgi/.eclipsefdn](https://github.com/osgi/.eclipsefdn) |

| How to contribute | [CONTRIBUTING.md](CONTRIBUTING.md) |
| The former monorepo | see [The former monorepo](#the-former-monorepo) at the end |

## How new specifications are developed

New specifications and non-trivial enhancements of existing ones go through
two discussions. [CONTRIBUTING.md](CONTRIBUTING.md) has the details.

1. **Requirements discussion, in this repository.** Open a tracking issue with
   the [`requirements`](https://github.com/osgi/osgi/labels/requirements)
   label, and write the requirements document `.design/requirements-XXX.md`
   in a branch `requirements/XXX`, where `XXX` is the issue number. The
   discussion concludes with a lazy consensus vote of the project committers
   on the osgi-dev mailing list that stays open for at least 72 hours.
2. **Design discussion, in the specification repository.** Once the
   requirements are accepted, the design is discussed in the repository of
   the specification. For a new specification, that repository is created
   first. The design document `.design/design-XXX.md` lives in a branch
   `design/XXX` of that repository. The discussion concludes with a vote of
   at least 3 project committers, with more `+1` than `-1`, that stays open
   for at least 72 hours.
3. **Specification, API and TCK** are then developed in the specification
   repository, together with a compatible implementation.

## Contributing

- **A requirement or an idea for a new specification:** open an issue here.
- **A bug in, or a change to, an existing specification:** open an issue or a
  pull request in its specification repository.
- Contributions need a signed
  [Eclipse Contributor Agreement](https://www.eclipse.org/legal/eca/), and
  commits must be signed off (`git commit -s`) with the e-mail address of the
  Eclipse account.

## The former monorepo

<details>
<summary>Where the last state of the monorepo is</summary>

Until the split into one repository per specification, all specifications,
reference implementations and TCKs were developed together in this
repository with a Gradle and bnd build. Its last state is kept read-only:

- branch [`main_archive`](https://github.com/osgi/osgi/tree/main_archive):
  the last state of `main`, commit
  [`8c7184d`](https://github.com/osgi/osgi/commit/8c7184dad43779668052afe5b29a2a201e527b52)
  of 2026-07-13; locked, nobody can push to it
- tag [`monorepo-final`](https://github.com/osgi/osgi/releases/tag/monorepo-final):
  the same commit

The release branches (`core`, `cmpn`, `enterprise`, `residential`, `release`)
and the release tags (`r4` … `r8`, `r401-*`) stay as they are; no tag can be
moved or deleted.

The draft specifications built from the monorepo remain at
<https://osgi.github.io/osgi/core/> and <https://osgi.github.io/osgi/cmpn/>.
They are no longer updated.

Every specification repository carries the complete history of its files from
this repository. The files were moved into the Maven layout in a single
commit, so use `git log --follow <file>` there to see the whole history.

The open pull requests and issues from the monorepo time stay here until they
are moved to their specification repositories.

</details>
